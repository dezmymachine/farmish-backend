# Runbook: media storage (Cloudflare R2 + local stand-in)

Clients upload images straight to object storage with short-lived presigned
PUTs; the API only signs and tracks them (`media_objects`). Production is
**Cloudflare R2**, reached through its S3-compatible API. Locally the API
points at the compose **rustfs** service, which speaks the same protocol
(ADR-0016).

## Local: bring the stand-in up

```bash
make rustfs-up            # 127.0.0.1:9000, dev credentials
make run                  # .env.example already points R2_* at it
```

`make test` starts it too (`MEDIA_TEST_S3_ENDPOINT`, `MEDIA_TEST_S3_REQUIRED=1`).
The bucket `farmish-dev` must exist; create it once with any S3 client, e.g.
the AWS CLI:

```bash
aws --endpoint-url http://127.0.0.1:9000 s3 mb s3://farmish-dev   # or skip
```

The public base URL (`R2_PUBLIC_BASE_URL`) is what the API returns as
`publicUrl`. With the stand-in it is only useful if the bucket allows
anonymous reads; without a public-read policy, verify an object with the S3
API instead:

```bash
aws --endpoint-url http://127.0.0.1:9000 s3 cp s3://farmish-dev/listings/.../x.jpg -
```

## Production: the R2 console checklist

1. **Create the bucket** (e.g. `farmish-media-prod`) and note the name.
2. **API token:** R2 → Manage R2 API Tokens → Create API token →
   **Object Read & Write**, scoped to that bucket only. Copy the Access Key
   ID and Secret Access Key into Railway as `R2_ACCESS_KEY_ID` /
   `R2_SECRET_ACCESS_KEY`. The token value is shown once.
3. **Account ID:** the R2 overview page → `R2_ACCOUNT_ID`. The API derives
   the endpoint `https://<account>.r2.cloudflarestorage.com`.
4. **Public read:** Bucket → Settings → Public access → either connect a
   custom domain (e.g. `media.farmish.gh`) or enable the `r2.dev` dev
   subdomain. Put that base URL in `R2_PUBLIC_BASE_URL`. R2 has no per-object
   ACLs: public reading is a bucket setting.
5. **CORS:** Bucket → Settings → CORS policy. Browsers PUT directly, so
   allow the frontend origins, `PUT`, and the `Content-Type` header:

   ```json
   [{
     "AllowedOrigins": ["https://farmish.gh", "http://localhost:3000"],
     "AllowedMethods": ["PUT", "GET", "HEAD"],
     "AllowedHeaders": ["Content-Type"],
     "ExposeHeaders": ["ETag"],
     "MaxAgeSeconds": 3600
   }]
   ```

   Without this the browser refuses the upload even though the presign is
   valid.
6. **Lifecycle (belt and braces):** Bucket → Settings → Object lifecycle →
   auto-delete objects after 1 day. The API's own `media.cleanup_orphans`
   sweep already deletes unclaimed uploads after 24 hours; the lifecycle rule
   is a second line of defence for objects whose row was lost.
7. **Never** set `R2_ENDPOINT` in staging/production: config refuses it, so a
   local URL can never leak into a deployment.

## Notes

- Presigned URLs are bearer secrets for 10 minutes. The API logs the object
  key, never the URL; do not log it client-side either.
- The presign signs `Content-Type` **and** `Content-Length`. A client that
  sends a different body is rejected by storage (403). This is what stops a
  5 GB upload to our bucket.
- The bucket needs no credentials from the browser: uploads are authorised
  only by the presigned URL.
